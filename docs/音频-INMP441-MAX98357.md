# INMP441 + MAX98357 在树莓派 4B 上的语音方案

> 结论：**可以接，硬件兼容；但软件不是即插即用。**
> Pi 4B 只有一组 I2S，麦克风和功放要共享时钟，必须配置设备树/ALSA。
> 如果只是想先跑通语音，USB 耳麦更省事；想做成一体化桌宠，再上这套 I2S。

---

## 1. 两个模块分别做什么

| 模块 | 作用 | 方向 |
|---|---|---|
| INMP441 | 全向 MEMS 麦克风，I2S 数字输出 | 麦克风 → 树莓派 |
| MAX98357 | I2S DAC + 3W D 类功放 | 树莓派 → 喇叭 |

MAX98357 是**单声道**功放，接一个喇叭即可；想要立体声需要两片或立体声版本。INMP441 也是单声道麦克风，对语音交互足够。

两者都是 **I2S 从设备**，树莓派做 I2S 主机，负责产生：
- `BCLK`：位时钟
- `LRCLK/WS`：左右声道时钟

所以它们可以共用 `BCLK` 和 `LRCLK`，但数据线要分开：

```text
INMP441  SD  ──────► Pi GPIO20（麦克风数据输入）
MAX98357 DIN ◄────── Pi GPIO21（音频数据输出）
```

## 2. 接线

### Pi 4B 40 针

| 信号 | 树莓派 | INMP441 | MAX98357 |
|---|---|---|---|
| 位时钟 BCLK | GPIO18（物理 12） | `SCK` | `BCLK` |
| 左右时钟 LRCLK | GPIO19（物理 35） | `WS` | `LRC` |
| 麦克风数据 | GPIO20（物理 38） | `SD` | — |
| 音频数据 | GPIO21（物理 40） | — | `DIN` |
| 3.3V | 物理 1 | `VDD` | — |
| 5V | 物理 2 或 4 | — | `VIN` |
| GND | 物理 6/9/14 等 | `GND` | `GND` |
| 声道选择 | — | `L/R` 接 GND 或 3.3V | — |
| 功放使能 | GPIO16（物理 36） | — | `SD` |
| 增益 | — | — | `GAIN` 按需接 |

说明：

- **INMP441 只能接 3.3V**，不要接 5V。
- 接线/改线前先断电；I2S 模块不支持带电热插拔。
- **MAX98357 的 `VIN` 建议接 5V**，音量和功率更足；接 3.3V 也能响，但功率小。
- INMP441 的 `L/R`：
  - 接 GND：左声道；
  - 接 3.3V：右声道。
  软件录立体声后取对应声道即可。
- MAX98357 的 `SD`：
  - 用 `googlevoicehat-soundcard` 覆盖层时，接 **GPIO16**，由驱动控制功放开关；
  - 用 `max98357a` 覆盖层时，可以接 3.3V 常开。
- `GAIN` 先按默认/悬空，音量用软件调；不要一上来就最大增益。
- 两个模块必须**共地**。
- MAX98357 的喇叭输出是 **BTL 桥接输出**：喇叭两端直接接 `+` / `-`，**不要**把任何一端接 GND，也不要把喇叭线碰到地。
- 在 MAX98357 的 `VIN` 和 `GND` 之间并 **100µF 电解 + 0.1µF 陶瓷**，靠近模块放置。
- 喇叭线尽量短、绞合，远离麦克风和 I2S 时钟线。

## 3. 软件配置：先试全双工覆盖层

Pi 4B 的 I2S 默认没有同时暴露“麦克风 + 功放”的声卡。最值得先试的是 Google Voice HAT 的覆盖层，它使用同一组 I2S 引脚，并且用 GPIO16 控制功放：

```bash
# Bookworm 是 /boot/firmware/config.txt；旧系统是 /boot/config.txt
sudo cp /boot/firmware/config.txt /boot/firmware/config.txt.bak

sudo nano /boot/firmware/config.txt
```

找到：

```ini
dtparam=audio=on
```

改成：

```ini
#dtparam=audio=on
dtoverlay=googlevoicehat-soundcard
```

然后重启：

```bash
sudo reboot
```

检查声卡：

```bash
aplay -l
arecord -l
```

如果出现一个同时有播放和录音的声卡，就成功了一半。

> 这类 I2S 声卡在录音时可能会把播放静音，或者反过来。我们的语音助手是半双工（先录完再播），所以即使不能真正同时录放，也不影响使用。

### 测试播放

先看 `aplay -l` 里的 card/device，例如 `card 1: voicehat`，然后：

```bash
speaker-test -D plughw:1,0 -t sine -f 440 -c 2 -l 1
```

### 测试录音

INMP441 是 24 位数据，通常用 32 位槽接收：

```bash
arecord -D plughw:1,0 -f S32_LE -r 48000 -c 2 -d 3 /tmp/i2s_mic.wav
aplay -D plughw:1,0 /tmp/i2s_mic.wav
```

如果录出来是双声道但只有一边有声音，这是正常的：INMP441 只占左或右声道。后面转成单声道即可。

### 检查内核日志

```bash
dmesg | grep -iE 'snd|i2s|voicehat|max98357'
```

## 4. 如果全双工覆盖层不行

`googlevoicehat-soundcard` 是给 Google Voice HAT 的，不是为 INMP441 + MAX98357 定制的，**不保证一次成功**。退路有两条：

### 方案 A：MAX98357 输出 + USB 麦克风

```ini
#dtparam=audio=on
dtoverlay=max98357a
```

MAX98357 的 `SD` 接 3.3V 常开，`DIN/BCLK/LRC` 按上表接。
USB 麦克风走 USB 声卡，和 I2S 功放互不干扰。

这是最稳的“半 I2S”方案：

```text
USB 麦克风 → 树莓派 → MAX98357 → 喇叭
```

### 方案 B：INMP441 输入 + USB 音箱/耳麦

保留 I2S 麦克风，输出用 USB 声卡。适合你想先保证录音质量、又不想调功放的情况。

> 我们的语音助手是**半双工**：先录音，再播放，不需要同时录放。
> 所以“麦克风和喇叭走不同声卡”完全没问题，反而更简单。

## 5. 和现有 voice_chat.py 的适配

当前 [voice_chat.py](../scripts/voice_chat.py) 的录音参数是给 USB 麦克风准备的：

```text
arecord -f S16_LE -r 16000 -c 1
```

INMP441 往往需要：

```text
arecord -f S32_LE -r 48000 -c 2
```

然后转成 Vosk 需要的 16kHz 单声道 16-bit：

```bash
sudo apt install -y sox

sox /tmp/i2s_mic.wav -c 1 -r 16000 -b 16 /tmp/mic16.wav remix 1
```

如果麦克风接的是右声道（`L/R` 接 3.3V），把 `remix 1` 改成 `remix 2`。

或者用 ffmpeg：

```bash
ffmpeg -y -i /tmp/i2s_mic.wav -ar 16000 -ac 1 -sample_fmt s16 /tmp/mic16.wav
```

等硬件确认后，可以给 `voice_chat.py` 加：

```text
--record-format S32_LE
--record-channels 2
--record-rate 48000
--convert-to 16000
--playback-device plughw:1,0
```

这样就能直接使用 I2S 麦克风和功放。

## 6. 声学上的坑

1. **单麦克风 + 喇叭容易回授**：麦克风不要正对喇叭，尽量隔开，加海绵/橡胶减震。
2. **INMP441 是全向的**：好处是 360° 能听到，坏处是风扇、键盘、空调噪声都会进来；桌面近场使用没问题，远场唤醒词会比麦克风阵列差。
3. **MAX98357 功放噪声**：电源要干净，喇叭线远离麦克风；音量先设 30–50%。
4. **不要同时全双工对话**：先做半双工，播放时暂停录音，能省掉 AEC（回声消除）。
5. **供电**：MAX98357 峰值电流不小，Pi 4B 用官方 5V/3A 电源；如果一放音就重启，给功放单独 5V 供电并共地。

---

## 7. 建议

- 如果你**已经买了** INMP441 + MAX98357：先按第 3 节试 `googlevoicehat-soundcard`；不行就退回“USB 麦克风 + MAX98357”或“INMP441 + USB 音箱”。
- 如果你**还没买**：先用 30–40 元的 USB 耳麦把语音链路跑通，再换 I2S。桌宠第一阶段最重要的是软件闭环，不是音频硬件。
- 如果你想要**一体化外壳**：INMP441 + MAX98357 更合适，但预留至少半天到一天调 ALSA。

---

## 8. 最小验收顺序

```text
1. 接线，检查 3.3V / 5V / 共地
2. 改 config.txt，重启
3. aplay -l / arecord -l 能看到声卡
4. speaker-test 能响
5. arecord 能录，aplay 能回放
6. sox 转 16k 单声道
7. 用 Vosk 识别一段中文
8. 再把 voice_chat.py 接到这个设备
```

不要一上来就跑完整语音对话；先让“能响、能录”各自通过。

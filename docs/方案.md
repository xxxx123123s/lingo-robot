# 树莓派桌宠：低成本分模块落地方案

> **路线已调整：先做人脸 + 语音，电机/履带后置。**
> 现在请优先看 [人脸 + 语音优先路线](方案-人脸语音优先.md)；本文保留为采购、供电、接线和以后装电机时的参考。

> 目标：用你已有的树莓派和摄像头，加尽量少的零件，做出一台能联网对话、识别人脸、用履带移动的桌宠。
>
> 原则：每个模块独立测试、独立验收，不通不过。本文保留“电机优先”的原始顺序，实际执行请按上面的新路线。

---

## 0. 结论先说

### 推荐架构

```text
                  ┌──────────────────────────────┐
                  │        树莓派 4 / 5           │
                  │                              │
   USB 麦克风 ───►│ 唤醒/VAD → ASR → 大模型 → TTS │───► USB 音箱
                  │        │                     │
   Pi 摄像头 ────►│  人脸检测/识别 → 行为状态机   │
                  │        │                     │
                  │  运动控制器（带看门狗）        │
                  └────────┼─────────────────────┘
                           │ GPIO / PWM
                    ┌──────▼──────┐
                    │  TB6612FNG  │
                    └──────┬──────┘
                    左电机 │ 右电机
                    ┌──────▼──────┐
                    │  履带底盘    │
                    └─────────────┘
```

### 最省钱的做法

- **树莓派**：用你已有的。Pi 5 最好；Pi 4 4GB 够用；Pi 4 2GB 就把语音识别放云端。
- **摄像头**：用你已有的。CSI 摄像头用 `picamera2`，USB 摄像头用 OpenCV。
- **运动**：履带底盘套件（含两个 TT 电机）+ TB6612FNG。
- **音频**：先用一个 **USB 耳麦**（麦克风和喇叭一体，约 30 元），比分开买更便宜，也方便做半双工对话。
- **供电**：台架阶段树莓派用官方电源/充电宝，电机用 4 节 AA 镍氢电池。**两路电源只共地**，最便宜也最安全。
- **显示**：第一版不要买屏幕，用 SSH + 手机网页控制。以后想加表情，再买 0.96 寸 OLED（约 10 元）。
- **云台**：第一版不要买舵机。人脸跟随先让整台机器人慢慢转，结构简单、少一个故障点。

### 不建议省的地方

- 电机驱动别用 L298N：压降大、发热大，电池供电时更明显。TB6612 只贵几块钱。
- 电机不要从树莓派 5V 取电：轻则重启，重则烧稳压器。
- 不要买来路不明的裸 18650 电芯和廉价充电器。
- 不要照抄用 `RPi.GPIO` 或 `pigpio` 的旧教程：**Pi 5 不支持这两个库**，用 `gpiozero + lgpio`。

## 1. 先确认你手上的树莓派

在树莓派上运行：

```bash
cat /proc/device-tree/model; echo
free -h
uname -m
cat /etc/os-release | grep PRETTY_NAME
libcamera-hello --list-cameras
arecord -l
aplay -l
```

也可以直接运行本项目脚本：

```bash
bash scripts/check_pi.sh
```

把输出发给我，我按你的型号出后续代码。

### 型号与能力预期

| 型号 | 人脸检测 | 本地语音识别 | 建议 |
|---|---|---|---|
| Pi 5 4GB/8GB | 15–30 FPS @640×480 | SenseVoice small 可实时 | 首选，注意散热和 5V/5A 供电 |
| Pi 4B 4GB | 8–15 FPS | Whisper tiny/base 或 Vosk | 可用，降低分辨率 |
| Pi 4B 2GB | 5–10 FPS | 建议云端 ASR | 内存紧，别同时跑大模型 |
| Pi 4B 1GB | 3–8 FPS | 云端 | 只适合做简单演示 |
| Pi Zero 2 W | 很低 | 云端 | 不推荐做完整视觉+语音 |

> 以上是量级预估，实际取决于摄像头、分辨率和散热。以 M2 实测为准。

### 摄像头

- **CSI 排线摄像头**（Pi Camera v1/v2/v3）：用 `libcamera` / `picamera2`，不要用 `cv2.VideoCapture(0)` 直接打开。
- **USB 摄像头**：一般是 `/dev/video0`，OpenCV 可以直接打开。
- v2 是固定焦距，拍 0.5–1.5 米的人脸要手动调焦；v3 自动对焦，更适合桌宠。
- 人脸识别不需要高分辨率：**640×480 足够**，越高越卡。

## 3. 供电与接线

### 3.1 最便宜的安全方案：两路电源

```text
[树莓派官方电源 / 5V 充电宝]
        │ USB-C
        ▼
     [树莓派]  GPIO GND ─────────────┐
        │ GPIO 12/13/5/6/16/26/23  │
        ▼                          │
     [TB6612FNG]                   │
        │ VM                         │
        ▼                          │
[4×AA 电池盒] + ──[开关]──[保险丝]──┘
        │
        └──────── GND ────────────── 共同接地
```

要点：

1. **树莓派和电机电池只共地**，不共 5V。
2. 电机电池正极先过开关，再过一个 2A/3A 保险丝，然后进 TB6612 的 `VM`。
3. TB6612 的逻辑 `VCC` 接树莓派 **3.3V**，不是 5V。
4. 在 TB6612 的 `VM` 和 `GND` 之间并在 470µF 电解电容；每个电机端子间并在 0.1µF 陶瓷电容，减少干扰。
5. 第一次测试把机器人**架空**，轮子悬空。

### 3.2 TB6612 接线表

| TB6612 | 树莓派 | 说明 |
|---|---|---|
| `VCC` | 3.3V（物理引脚 1） | 逻辑电源，不要接 5V |
| `GND` | GND（物理引脚 6） | 必须和电池负极共地 |
| `VM` | 电池 +（经开关/保险丝） | 电机电源 4.8–6V |
| `STBY` | GPIO 23（物理引脚 16） | 高电平使能；低电平急停 |
| `AIN1` | GPIO 5（物理引脚 29） | 左电机方向 |
| `AIN2` | GPIO 6（物理引脚 31） | 左电机方向 |
| `PWMA` | GPIO 12（物理引脚 32） | 左电机调速 |
| `BIN1` | GPIO 16（物理引脚 36） | 右电机方向 |
| `BIN2` | GPIO 26（物理引脚 37） | 右电机方向 |
| `PWMB` | GPIO 13（物理引脚 33） | 右电机调速 |
| `AO1/AO2` | 左电机 | 转向反了就交换这两根 |
| `BO1/BO2` | 右电机 | 转向反了就交换这两根 |

> 如果你用 I2S 麦克风 HAT，会占用 GPIO 18–21，本表已经避开；但仍建议第一版用 USB 音频，少一类问题。

### 3.3 关于 Pi 5 的供电

- Pi 5 官方电源是 **5V/5A（27W）**；用 5V/3A 也能开机，但 USB 外设和性能会受限。
- 摄像头 + USB 音频 + Wi-Fi 同时工作时，廉价 5V/2A 电源很容易导致重启。
- 台架测试先用官方电源；装车后再考虑电池 + 5V/5A 降压。
- Pi 5 一定要加主动散热，温度到 80°C 会降频。

### 3.4 以后升级成单电池

```text
[2S 18650 带保护板 7.4V] ──[保险丝/开关]──┬──► TB6612 VM
                                          │
                                          └──► 5V/5A 降压 ──► Pi 5 USB-C
```

- 2S 满电 8.4V，TT 电机额定 3–6V，直接给会超压；软件限速 50–60%，或加 6V 降压。
- 5V/5A 降压模块要买口碑好的，廉价 XL4015 标 5A 实际要加散热，别长时间满载。
- 电池充电时不要装在机器人里充。

## 4. 软件选型

| 功能 | 第一版选择 | 备选 | 说明 |
|---|---|---|---|
| 系统 | Raspberry Pi OS Bookworm 64-bit | Ubuntu 24.04 | Pi 5 必须 Bookworm 或更新 |
| Python | 系统自带 3.11 | 3.12 | 用 venv，加 `--system-site-packages` |
| 摄像头 | `picamera2`（CSI）/ OpenCV（USB） | — | CSI 不要用 `VideoCapture(0)` |
| 人脸检测 | OpenCV YuNet | Haar Cascade | YuNet 小而快，CPU 足够 |
| 人脸识别 | OpenCV SFace | LBPH | 不用 dlib，省编译痛苦 |
| 唤醒 | 先网页/按钮，后 openWakeWord | Porcupine | 中文自定义唤醒词要训练 |
| VAD | webrtcvad | Silero VAD | 判断一句话有没有说完 |
| ASR | sherpa-onnx + SenseVoice small int8 | Vosk / 云端 | Pi 4 2GB 优先云端 |
| 对话 | DeepSeek / 通义千问 API | OpenAI 兼容接口 | 树莓派不跑本地大模型 |
| TTS | Edge TTS | Piper 本地 | Edge 自然但依赖网络 |
| 运动 | `gpiozero` + `lgpio` | PCA9685 | Pi 5 不要用 `RPi.GPIO`/`pigpio` |
| Web | FastAPI + WebSocket | Flask | 视频用 MJPEG 最简单 |
| 数据 | SQLite + `.npz` | — | 人脸特征本地保存，不上传 |

### 4.1 为什么不用 `face_recognition`

`face_recognition` 依赖 dlib，在树莓派上编译慢、内存占用高，Pi 5 上还容易遇到兼容问题。OpenCV 的 YuNet + SFace 是现成 ONNX 模型，CPU 推理快，安装简单。

### 4.2 语音链路

```text
麦克风 16kHz 单声道
   │
   ├─ 唤醒词（或按钮）──► 进入聆听
   │
   ├─ VAD 检测说话结束（静音 700–800ms）
   │
   ├─ ASR 转文字
   │
   ├─ 大模型（带工具调用）
   │
   └─ TTS 播放 ──► 播放期间麦克风静音（半双工，防回声）
```

### 4.3 延迟预期

| 环节 | 目标 |
|---|---:|
| 唤醒 | < 0.5s |
| 说完到出文字 | 1–3s |
| 大模型首字 | 1–3s |
| TTS 首句 | 0.5–2s |
| 端到端 | 3–6s（可接受） |

如果超过 8 秒，用户就会觉得“它没理我”。先把链路跑通，再优化。

### 4.4 工具调用（让对话能控制运动）

不要让大模型直接输出 PWM。只暴露安全、有限的工具：

```text
move(direction: forward|backward|left|right, speed: 0.0–0.6, duration_ms: 0–2000)
stop()
look(pan_deg, tilt_deg)        # 有云台才启用
set_expression(emotion)        # happy|curious|sleepy|surprised
remember(key, value)
recall(key)
```

工具层负责：

- 限速、限时长；
- 收到 `stop` 或检测到障碍立即停；
- 大模型超时/报错时自动停；
- 记录每次动作，方便复盘。

## 5. 分模块打通路线

> 每个模块都要能**单独运行、单独验收**。不要在一个脚本里同时开摄像头、麦克风和电机。

### M0：系统与硬件盘点（0.5 天）

**目标**：确认型号、内存、系统、摄像头、声卡、GPIO 都正常。

**做**：

```bash
bash scripts/check_pi.sh
```

手动补测：

```bash
# CSI 摄像头拍照
libcamera-still -o ~/camera_test.jpg --width 1280 --height 720 -t 2000 -n

# USB 摄像头
ls -l /dev/video*

# 录音 3 秒
arecord -f cd -d 3 ~/mic_test.wav
aplay ~/mic_test.wav

# GPIO 自检（可选）
python3 -c "import gpiozero; print(gpiozero.__version__)"
```

**验收**：

- 能读出 Pi 型号和内存；
- 摄像头能保存一张清晰照片；
- 能录 3 秒、能播放；
- `vcgencmd get_throttled` 没有持续欠压；
- 温度待机 < 65°C。

**常见坑**：

- Pi 5 没有 3.5mm 耳机孔，插 3.5mm 耳麦没声音是正常的。
- CSI 摄像头排线方向插反会检测不到；断电再插。
- 廉价电源会导致 `throttled=0x50000`，先换电源再调软件。

---

### M1：电机与履带（1–2 天）

**目标**：两个电机方向正确、能调速、能急停。

**准备**：

- 履带底盘装好，电机线先不固定死；
- TB6612 按第 3 节接线；
- 机器人架空。

**做**：

```bash
python3 scripts/test_motor.py --dry-run   # 只看引脚
python3 scripts/test_motor.py --yes       # 架空空转
```

测试顺序：

1. 左轮正转 1 秒；
2. 右轮正转 1 秒；
3. 双轮正转 1 秒；
4. 双轮反转 1 秒；
5. 原地左转/右转各 1 秒；
6. 停止。

**验收**：

- 左轮、右轮方向与代码一致；
- 30% 速度能稳定慢转，不尖叫、不卡顿；
- Ctrl-C 能在 0.5 秒内停；
- 电机启动时树莓派不重启、不花屏；
- 手挡住轮子 1 秒，驱动不冒烟（不要长时间堵转）。

**调试**：

- 某侧反了：交换该电机 `AO1/AO2` 两根线，或代码里加 `--left-invert` / `--right-invert`。
- 一侧不转：先量 TB6612 `STBY` 是否高电平，再量 `VM` 是否有电池电压。
- 一启动就重启：电源问题，先分电源、共地、加电容，不要先怀疑代码。
- 低速不转：TT 电机有死区，最小速度从 0.25–0.3 开始。

**注意**：

- 便宜履带底盘没有编码器，只能“按时间走”，走直线会偏，这是正常的。
- 想走直线/精确转向，下一步加编码器或换 N20 电机 + 电机驱动板。

---

### M2：摄像头与人脸检测（1 天）

**目标**：实时看到画面，框出人脸。

**做**：

1. CSI 摄像头：用 `picamera2` 抓 640×480 的 numpy 帧；
2. USB 摄像头：OpenCV `VideoCapture(0)`；
3. 用 YuNet 检测人脸，画框，显示 FPS；
4. 保存一张带框截图。

**验收**：

- Pi 5：≥15 FPS；Pi 4：≥5 FPS；
- 0.5–2 米内能稳定框住正脸；
- 侧脸/遮挡会漏检，属正常；
- 连续运行 10 分钟不崩溃、不越来越卡。

**常见坑**：

- CSI 摄像头用 `cv2.VideoCapture(0)` 打不开，必须用 `picamera2`。
- 画面颜色不对：OpenCV 是 BGR，`picamera2` 默认 RGB，要转换。
- 分辨率越高越慢，先固定 640×480。
- 逆光/顶光会影响检测，桌宠摄像头最好略高于人脸。

---

### M3：人脸识别与跟随（1–2 天）

**目标**：认出 3 个已知的人，陌生人标 unknown；摄像头能朝人脸方向转。

**做**：

1. 每人录 10 张不同角度/光照的照片；
2. 用 SFace 提取特征，保存 `.npz`；
3. 计算余弦相似度，超过阈值判为已知；
4. 画面显示名字；
5. 根据人脸中心 x 坐标，控制原地左/右转（先只在桌面上小角度测试）。

**验收**：

- 每个人 10 次测试至少认对 8 次；
- 陌生人不会被叫成某个人；
- 跟随有 5%–10% 的死区，不会左右抖；
- 人脸丢失 2 秒后自动停；
- 机器人转动时不会把自己转下桌（没有悬崖传感器就限制角度/时间）。

**常见坑**：

- 阈值不要照搬，按你的摄像头和光照校准；先用 0.363 试。
- 录入和识别的人脸尺寸差异大，会影响准确率；检测框留一点边距。
- 不要用识别结果做门禁/支付，这只是玩具级。
- 人脸特征只存本地，不上传云端。

---

### M4：音频输入输出（1 天）

**目标**：能录到清晰语音，能播放 TTS。

**做**：

```bash
arecord -l
aplay -l
arecord -f cd -d 3 ~/mic_test.wav
aplay ~/mic_test.wav
speaker-test -t sine -f 440 -c 1 -l 1
```

**验收**：

- 录音回放能听清自己说话；
- 无明显爆音/底噪；
- 音箱音量够用但不刺耳；
- 播放时麦克风不会把喇叭声收进去（半双工：播放时暂停录音）。

**常见坑**：

- Pi 5 没有 3.5mm 孔；用 USB 声卡/耳麦。
- 默认声卡不对：`arecord -l` 看 card/device，用 `-D plughw:CARD,DEVICE` 指定。
- USB 耳麦的麦克风和喇叭可能是两个设备，要分别指定。
- 廉价 USB 音频有底噪，VAD 阈值要相应调高。

---

### M5：语音识别、对话、TTS（2–4 天）

**顺序很重要**，不要一上来就接麦克风：

1. **纯文字对话**：终端输入 → 大模型 → 终端输出。先验证 API、人格、工具调用。
2. **TTS**：把回复转成语音播放。
3. **ASR**：录音 → 文字，先不做唤醒词，按回车开始/结束。
4. **VAD**：自动判断说完。
5. **唤醒词**：最后再加。

**验收**：

- 说“你好”，3–6 秒内开始回应；
- 说“向前走”，机器人走 0.5 秒后停；
- 说“停”，0.2 秒内停，不经过大模型；
- 断网时能说“网络好像断了”，而不是死机；
- 大模型 15 秒超时，电机保持停止。

**省钱建议**：

- 大模型用 DeepSeek/通义千问的 OpenAI 兼容接口，按量计费，日常对话很便宜。
- TTS 先用 Edge TTS（免费但非官方，可能失效）；要稳定离线再换 Piper。
- 常用回复（“我在”“网络断了”“好的”）做本地缓存，减少延迟和费用。
- 设置 `max_tokens`，人格提示词要求“回答不超过两句话”，TTS 才不会念一大段。

**常见坑**：

- 不要用树莓派跑 7B 本地大模型，体验会很差。
- 云端 ASR 要确认是否上传音频；人脸和音频的隐私策略要分开考虑。
- 播放 TTS 时继续录音会产生回声，先做半双工。
- 中文唤醒词“你好小派”需要自定义模型；第一版用网页按钮/回车，别卡住。

---

### M6：行为状态机与整机联调（2–3 天）

**目标**：把视觉、语音、运动串起来，任何异常都能停下来。

**状态**：

```text
IDLE ──唤醒/按钮──► LISTEN ──VAD结束──► THINK ──► SPEAK ──► IDLE
  │                    │                  │
  │                    └─超时/没听清──────┘
  │
  ├─检测到人脸──► TRACK（只转小角度）
  └─收到移动指令──► MOVE（限时/限速）
```

**必须有的保护**：

- 运动看门狗：500ms 没收到新命令就停；
- 全局 `stop`：语音“停”、网页急停、Ctrl-C、SIGTERM 都走同一条路径；
- 大模型工具调用参数校验：速度、时长、方向都白名单；
- 摄像头/麦克风线程崩溃不影响电机停止；
- 启动时先 `STBY=0`，初始化完成后再使能。

**验收**：

- 连续 20 条随机指令，不出现失控；
- 拔掉网络，机器人停下并说话提示；
- 强制关闭程序，电机在 0.5 秒内停；
- 急停开关一按，电机断电。

---

### M7：网页控制台与整机（2–3 天）

**目标**：手机同 Wi-Fi 能看画面、发消息、控制移动、急停。

**功能**：

- MJPEG 视频流；
- 状态显示（IDLE/LISTEN/THINK/SPEAK）；
- 方向按钮 + 急停；
- 文字聊天；
- 人脸录入；
- 日志。

**安全**：

- 只监听局域网，不要端口转发到公网；
- 加一个简单 token；
- 网页急停按钮必须调用和语音“停”相同的底层函数。

**结构**：

- 电池放最低、最中间；
- 摄像头略高于人脸；
- 履带留检修口；
- Pi 5 加散热风扇和通风孔；
- 履带不要太紧，桌面上加橡胶垫防滑。

**验收**：

- 手机视频延迟 < 500ms；
- 连续运行 30 分钟，CPU 温度 < 80°C；
- 满电运行 1 小时以上（AA 镍氢可能达不到，按实测）；
- 从 30cm 桌面边缘缓慢靠近时能停（如果装了红外/ToF）。

## 8. 常见坑清单

1. **用树莓派 5V 给电机供电** → 重启/烧稳压器。电机独立供电，只共地。
2. **L298N 压降** → 电池 6V 到电机只剩 4V 多。用 TB6612。
3. **Pi 5 用 `RPi.GPIO`/`pigpio`** → 不支持。用 `gpiozero + lgpio`。
4. **CSI 摄像头用 `cv2.VideoCapture(0)`** → 打不开。用 `picamera2`。
5. **用 `face_recognition`/dlib** → 编译久、内存高。用 YuNet + SFace。
6. **一上来就接唤醒词** → 中文自定义唤醒词要训练。先用按钮/网页。
7. **播放时继续录音** → 回声/自问自答。先半双工。
8. **没有运动看门狗** → 程序崩溃后电机一直转。必须有 500ms 超时停止。
9. **廉价电源** → 欠压重启，误以为是代码问题。先看 `vcgencmd get_throttled`。
10. **把机器人放在桌边测试** → 摔机。先架空，再限速，再加边缘检测。

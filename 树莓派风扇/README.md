# 树莓派 4B CPU 温控风扇（DRV8833 + 5V 小电机 + SG90 转向）

## 接线

| DRV8833 | 树莓派 4B | 40 脚编号 | 说明 |
|---|---|---|---|
| VM | 5V | Pin 4 | 电机电源 |
| GND | GND | Pin 6 | 必须与 Pi 共地 |
| VCC | 3V3 | Pin 1 | 逻辑电源 |
| SLP (nSLEEP) | 3V3 | Pin 1 | 与 VCC 共用，**必须硬接 3V3，不能接 GPIO** |
| AIN1 | GPIO12 | Pin 32 | **PWM 打这根**，调速全靠它 |
| AIN2 | GND | Pin 6 | 固定低电平，滑行端 |
| AO1 / AO2 | 电机两根线 | — | 接反只是反风，对调即可 |

注意 Pin 12 / Pin 18 不能用了：ST7789 屏的 BL=GPIO18、RST=GPIO24 已占用。

## 踩过的坑：把 DRV8833 当 TB6612 用

这块板子一开始按 TB6612 接线（PWMA 调速 + AIN1/AIN2 定方向 + STBY 使能），
现象是**一上电马达就全速转，占空比设 12% 还是 25%，声音一模一样，温度降到 40℃ 以下也不停**。

原因是两种芯片的输入逻辑根本不是一回事：

| | TB6612 | DRV8833 |
|---|---|---|
| 调速输入 | PWMA（独立引脚） | **没有，速度靠 IN1 上的占空比** |
| 方向 | AIN1 / AIN2 一高一低 | IN1 / IN2 一高一低 |
| 使能 | STBY 拉高 | nSLEEP 拉高（不是使能，是休眠） |
| 接错的表现 | — | IN 被拉成一高一低 = 直通全速，PWM 完全不起作用 |

照 TB6612 的思路接线时，`AIN2`（GPIO27）被程序拉高当"方向"，在 DRV8833 上
要么是刹车、要么是把芯片唤醒，而 PWM 那根要么没接到 IN1、要么只决定"醒不醒"不决定速度，
所以怎么调都是全速。

DRV8833 的四种输入组合：

| IN1 | IN2 | 结果 |
|---|---|---|
| **PWM** | **低** | 单极性驱动，平均电压 = 占空比 × 5V ✅ |
| 高 | 低 | 全速正转 |
| 低 | 低 | 滑行，真断电，停得住 |
| 高 | 高 | 刹车，转速一样但电流大、芯片发烫 |

判断有没有真的接对，最快的办法是 `python3 fan.py --test`：它会先不通电空等 3 秒，
**这 3 秒马达必须完全静止**。还在转就说明 IN 脚被电平拉死了，PWM 是空转的。

## PWM 频率：1kHz 换 8kHz

原来用 1kHz，正好落在人耳最敏感的频段，直流电机会把方波变成刺耳的"吱——"，
占空比降到 6% 也一样响 —— 这也是"降了还是很吵"的另一半原因。
改成 **8kHz** 后啸叫基本消失，等效电压不变，属于纯收益。

DRV8833 支持到 100kHz，但 lgpio 的软件 PWM 上限 10kHz，超过会报错。

## 供电：这是另一个坑

最初用 2A 充电器，风扇一启动树莓派就重启（实测连续 3 次），
并导致欠压反复断电、SD 卡写入损坏（`fan.py` 出现过 null bytes、文件被清零）。

换成**树莓派官方 5.1V/3A 电源**后实测：

| 测试 | 软启动 | 保持 | 电源标志采样 | 结果 |
|---|---|---|---|---|
| 70% 占空比 | 6 s | 6 s | 220 次全为 `0x0` | 通过，无重启 |
| **100% 占空比** | 6 s | 6 s | 220 次全为 `0x0` | 通过，无重启 |

`vcgencmd get_throttled` 的历史欠压位（bit16）只有**完全断电**才清零，
软重启不清。换电源后拔插一次，读到 `0x0` 才是干净基线。

结论：官方 3A 电源余量充足，满速都不掉压，不需要额外电容。

## 手动开关（触摸屏）

那块 ST7789 屏的**系统页第一行**就是风扇开关，点一下在三种模式间循环：

| 点击次序 | 显示 | 含义 |
|---|---|---|
| 开机默认 | 手动·关（灰） | 停着，等人工点开 |
| 第 1 下 | 手动开 100%（橙） | 不看温度，全速跑，舵机摆到吹风位 120° |
| 第 2 下 | 自动 N%（绿） | 按温度走，≥40℃ 起转，≤35℃ 停 |
| 第 3 下 | 手动·关（灰） | 停转，舵机收回到 0° |

循环顺序是 **关 → 手动开 → 自动 → 关**。起点定在"关"，因为开机就是这个状态，
所以最常用的动作是**点一下就直接全速**，不用先绕到自动再点。

橙绿分开是为了远远扫一眼就知道「现在是人在管还是自己在管」。

原理：`fan.py` 是独立的 root 服务，占着 GPIO12/23/27，屏幕那边（pi 用户）
不能直接碰引脚，两边靠 `/tmp` 下一对文件对话：

- 屏幕写 `/tmp/fan.cmd` → `auto` / `on` / `off`，也可以带数值：`on 0.25`
- 风扇写 `/tmp/fan.state` → `<模式> <占空比%> <温度>`

实测切换延迟 200~260ms，加上界面 0.8 秒缓存，点完约 1 秒内看到变化。
（软启动还要 6 秒才升到位，但状态文字会先变，不会让人以为没点上。）

现场调风量不用改代码重启，直接写文件就生效：

```bash
echo "on 0.25" | sudo tee /tmp/fan.cmd    # 立刻按 25% 转
```

不用屏幕也能切：

```bash
python3 fan.py --mode on      # 手动开
python3 fan.py --mode off     # 手动关
python3 fan.py --mode auto    # 交回温控
python3 fan.py --status       # 看当前模式
```

## SG90 转向舵机

风扇挂在小马达上吹不了几个方向，加一颗 SG90 把它**摆过去对着 CPU、不用时收回来**。

| SG90 | 树莓派 | 40 脚编号 |
|---|---|---|
| 棕（GND） | GND | Pin 6 |
| 红（VCC） | 5V | **Pin 2**（不要用 Pin 4，那是电机 VM） |
| 橙（信号） | GPIO13 | Pin 33 |

**为什么信号必须走 GPIO13。** 树莓派只有 PWM0 / PWM1 两个硬件通道，且只出现在
GPIO12/13/18/19 上：12 被风扇调速占了（8kHz）、18 是屏幕背光，19 和 13 同属 PWM1
不能各走各的，剩下的就 13 —— 走 PWM1，与风扇的 PWM0 是两套独立定时器，互不干扰。

**为什么不用 gpiozero 的 Servo。** 它会在这块脚上误判"没有硬件 PWM"，自动退回
SoftwarePWM 并警告 servo jitter。软件 PWM 的脉宽受 CPU 调度影响，舵机会原地哆嗦。
实测 `lgpio.tx_pwm` 在 GPIO13 上确实是硬件 PWM，所以 `servo.py` 直接调底层。

```python
lgpio.tx_pwm(h, pin, 50.0, duty)    # 位置参数是 (频率Hz, 占空比%)
```

注意 `lgpio.py` 里这两个形参名写成了 `pwm_frequency / pwm_duty_cycle`，
**按关键字传会传反**，结果发出"7.5Hz、50% 占空比"——每半周期 66ms 高电平，
远超 SG90 能接受的 2.5ms，舵机直接顶到一边死扛。按位置传才对。

**实测角度**：吹风位 **120°**，收起位 **0°**。0° 是物理下限（脉宽 0.50ms），
能到但长期顶着齿轮容易松，想留余量就设 5°（肉眼看不出区别）。

### 什么时候动、什么时候不动

关键设计：**舵机不跟着每一次风扇启停动作**。40℃ 起转、35℃ 停，空闲时可能
一分钟启停一次，舵机跟着来回摆，一天上千次，SG90 那种塑料齿轮撑不了几天。
所以绑在"工作状态"上，一天只动两次：

| 模式 | 舵机 | 风扇 |
|---|---|---|
| 自动（开机后默认） | 一直在 120° 吹风位 | 自己按温度启停 |
| 手动开 | 120° | 强制 100% |
| 手动关 | **0° 收起** | 停 |
| 服务停止 / 关机 | **0° 收起后松开**（detach，不再发力） | 停 |

退出时等 0.5 秒是必须的：`tx_pwm` 只是"开始发脉冲"，舵机还要几百毫秒才走到位，
这时候立刻 detach 会把它停在半路上。

舵机是可选的：没接、没装库、或 `FAN_SERVO=0`，任何异常都只打印一行，
风扇照常工作 —— 演示前别让一颗舵机把整个温控拖垮。

单独调角度：

```bash
python3 servo.py --sweep              # 30→150→30 慢扫，看清实际行程
python3 servo.py --angle 120          # 转过去保持住，方便比位置
python3 servo.py --angle 45 --hold 3  # 转过去停 3 秒后松开
```

**别一上来就试 0 和 180。** 便宜 SG90 实际行程普遍差 5~10°，两端会顶到机械限位
发出"咯咯"的堵转声，那个位置一直堵着，几十秒就能把塑料齿轮磨出间隙。
从 90 开始每次加 15° 往外试，听到咯咯声就退回上一档。

## 开机默认关闭：风扇不会自己起来

断电重开时 SoC 还是热的（刚跑过 50℃ 以上），一上电温度就过阈值，温控逻辑会
**立刻拉满** —— 而那正是整台机器最脆弱的时候：SD 卡在写、USB 在枚举、
电源还没稳。这时候多一路 5V 大电流纯属给自己找事（之前 2A 电源就是在这个
时刻欠压重启、把 SD 卡写坏的）。

所以 `fan.py` **每次启动（开机、重启、`systemctl restart`）都先把模式写成
`off`**：风扇不动、舵机收回到 0°，屏幕显示「手动·关」。要吹就点屏幕，
或者 `echo on | sudo tee /tmp/fan.cmd`。

写在模式文件里而不是只存在内存里，是为了让屏幕也看到真实状态 —— 否则屏幕上
还挂着上次的「自动 68%」，人以为它在转，其实早就停了。

想恢复"开机就按温度自动跑"：`FAN_BOOT_MODE=auto`（改 fan.service 的 Environment）。

## 部署

已作为 systemd 服务开机自启：

```bash
sudo systemctl status fan.service     # 看状态
sudo journalctl -u fan.service -f     # 看实时日志
sudo systemctl disable --now fan.service   # 不要风扇了
```

参数全部可用环境变量覆盖，改 `/etc/systemd/system/fan.service` 的 `Environment=`：

| 变量 | 默认 | 含义 |
|---|---|---|
| `FAN_ON` | 40 | 高于此温度起转（℃） |
| `FAN_OFF` | 35 | 低于此温度停转，5℃ 迟滞防抖 |
| `FAN_MIN` | 0.45 | 一开就明显在转的最低档（≈2.25V） |
| `FAN_MAX` | 1.00 | 上限 = 5V 全速，50℃ 时达到 |
| `FAN_KICK` | 0.95 | 起转瞬间的"踢一脚"占空比（≈4.75V） |
| `FAN_KICK_T` | 1.0 | 踢多久（秒） |
| `FAN_RAMP` | 2.0 | 从 KICK 滑回目标占空比用几秒 |
| `FAN_FULL` | 50 | 到这个温度用 `FAN_MAX` |
| `FAN_HZ` | 8000 | PWM 频率，听不见啸叫的起点 |
| `FAN_DRV` | drv8833 | 驱动芯片，换 TB6612 时设 `tb6612` |
| `FAN_SERVO` | 1 | 0 = 不用舵机，只风扇 |
| `FAN_ANGLE_ON` | 120 | 吹风位角度（实测值） |
| `FAN_ANGLE_OFF` | 0 | 收起位角度（0 是物理下限，想留余量设 5） |
| `FAN_BOOT_MODE` | off | 服务启动时的初始模式：off / auto / on |

温度到占空比的曲线：40℃ = 45%，50℃ 及以上 = 100%，中间线性。

**满速会不会烧？** 之前 4.3V 时芯片烫手，烫的不是电压，是接错成刹车态 ——
IN1/IN2 同时有效等于把电机两端短路，电流全变成热，转速还上不去。
现在 IN2 固定为低走单极性滑行，5V 全速的空载电流只有 0.1~0.2A，
DRV8833 的 MOSFET Rds_on ≈ 0.3Ω，功耗不到 0.05W，凉得很。
满速的代价只剩噪音和电机寿命，散热上没有任何问题。

**起转要「踢一脚」，不能慢慢爬。** 直流小马达的静摩擦远大于动摩擦：
从 0 平滑升到 30% 时，它前半段纹丝不动，电全变成线圈发热和"嗡嗡"声，
等爬过起转点才动 —— 表现为"启动困难、要等好几秒"。原来的 6 秒软启动
把这难受的时间又拉长了三倍。

现在的起转分三段：0.3 秒冲到 95%（避免电流阶跃，不直跳）→ 保持 1.0 秒
压过静摩擦 → 2 秒平滑滑回目标占空比（不直接掉，否则可能又停转）。
只有"停→转"走这套，运行中调速度不会重复踢。

**下限为什么是 45%。** 12%（0.6V）完全转不动，马达堵在那里不转就没有
反电动势，电流只受绕组电阻限制，**比正常转起来更烫**，还会"嗡嗡"响。
20% / 25% / 32% 能转，但肉眼几乎看不出在动。45% ≈ 2.25V 才是一开就
"看得出在转"的位置。判断标准：**转得起来的最低占空比再留一档余量**，不要照抄数字。

**阈值为什么是 40/35。** 中途试过 52/45，理由是 4B 空闲就在 40~45℃，
40 起转等于常开。但接对之后占空比真能调了，40 起转反而更合适：热一点就动，
演示时看得见。迟滞从 3℃ 拉到 5℃ 是因为满速时一分钟能降 3~4℃，
3℃ 迟滞会在 40 附近反复启停，每次启停都要踢一脚（95%），既吵又费电。

## 调试命令

```bash
python3 fan.py --status    # 只读：温度、电源状况、驱动类型、判断结果，不碰 GPIO
python3 fan.py --test      # 先静置 3 秒验证能停住 → 软启动 → 保持 6 秒 → 停
python3 fan.py --on        # 持续运行，Ctrl-C 停
python3 fan.py --off       # 立刻停
python3 fan.py --jog 3 --duty 0.2   # 低占空比点动，查接线/量电压用（先停服务）
FAN_ON=45 python3 fan.py   # 临时改阈值（演示时嫌吵就把起转点提高）
```

`fanprobe.sh [占空比]` 是压测脚本：后台起风扇，同时每 0.15 秒采样
`get_throttled` 并写 `/tmp/uv.log`，SSH 断线也不丢数据。

## 判断供电够不够

```bash
vcgencmd get_throttled
```

- 低 4 位是「此刻」：bit0 欠压、bit1 降频、bit2 限流、bit3 温度限制
- 高 4 位是「曾经」：bit16 曾欠压、bit17 曾降频、bit18 曾限流
- `0x0` 正常
- `0x50000` = 曾经欠压 + 曾经限流，是历史记录，不代表现在有问题

运行中只要 bit0 一直是 0，风扇就不会把树莓派拖重启。

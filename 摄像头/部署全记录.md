## 三、已完成：离线中文语音转文字 ✅

### 技术方案
- 引擎：**Vosk**（Kaldi 框架，离线运行）
- 模型：`vosk-model-small-cn-0.22`（42MB，中文小模型）
- 位置：`/home/pi/vosk-model-small-cn-0.22/`
- 脚本：`/home/pi/stt_live.py`（含 ×12 数字增益、实时分句输出）

### 使用方法（随时可用）
SSH 登录树莓派后执行（一键脚本 `/home/pi/stt.sh`）：
```bash
~/stt.sh
```
等价于完整命令：
```bash
arecord -D plughw:3,0 -f S16_LE -r 16000 -c 1 -t raw | python3 ~/stt_live.py
```
对麦克风说话 → 终端实时输出文字，格式 `[08.2s] 你好`，`Ctrl+C` 停止。

> 设计说明：stt_live.py 只从 stdin 读音频流，不含录音逻辑——录音由 arecord 负责，二者用管道解耦。
> 好处：换麦克风只改 arecord 参数、脚本可复用于文件/网络音频源、无需 pyaudio 依赖。

### 部署过程中的坑（重要）
1. **vosk 导入报 `cannot enable executable stack`**：trixie 新内核拒绝带执行栈标志的库
   → 修复：`sudo apt install patchelf && patchelf --clear-execstack ~/.local/lib/python3.13/site-packages/vosk/libvosk.so`
2. **pip 装包**要加 `--break-system-packages`
3. **apt 里没有 execstack 包**，用 patchelf 替代

### 提升准确率的路径（以后可选）
| 方案 | 说明 | 代价 |
|---|---|---|
| 换大模型 | `vosk-model-cn-0.22`（1.3GB），明显更准 | 下载 15h+（当前Wi-Fi），建议先拉网线 |
| 限定指令词表 | 桌宠只需识别固定命令，准确率≈100% | 改脚本，零成本 |

## 四、阻塞中：CSI 摄像头（硬件数据通道损坏，待换件）❌

### 已完成的软件配置（不用再动）
```
# /boot/firmware/config.txt 中已包含：
camera_auto_detect=0
dtparam=i2c_vc=on
dtoverlay=imx219
```

### 诊断结论
- 传感器芯片曾**成功识别过一次**（列出全部分辨率模式）→ 接口、方向、驱动、传感器本身都没问题
- 此后 I2C 时通时断 → **物理接触不良**
- 用户实测：pin15=3.3V（供电✅）、pin13/14=1.8V（I2C 线通，模块上拉电平偏低）
- **LED 现象已解释**：LED 接 GPIO，插 DIS 口"误亮"不代表 CAM 口异常

### 待做：剩余两张测试牌
1. **模块端翻转**：摄像头小板上的排线拔出，翻转 180°（触点换面）重插压实
2. **排线两端调头**：两端都是 15-pin，可整根调头换用另一段触点

两招都无效 → 判定排线或模块硬件损坏，换件（15-pin FFC 排线几块钱）。

### 2026-10-27 复测结论（配置与端口全部排除，锁定硬件）

复测环境：树莓派刚重启（uptime 数分钟），网络 ping 1ms / 丢包 0%（比之前 Wi-Fi 稳定得多）。

| 检查项 | 结果 | 判定 |
|---|---|---|
| `i2cdetect -y 10` | `10: UU`（0x10 被驱动占用） | ✅ 控制通道稳定（不再时通时断） |
| `rpicam-hello --list-cameras` | `imx219 [3280x2464 10-bit RGGB]`，8 个模式全列出 | ✅ 驱动枚举正常 |
| `csi@7e801000`（Unicam 1 = 标准口） | `okay` | ✅ 端口映射正确 |
| 抓图 1920×1080 | `Camera frontend has timed out` ×N，无输出文件 | ❌ 数据通道无帧 |
| 抓图 640×480（最低带宽） | 同样超时 | ❌ 排除带宽/速率问题 |
| 内核 dmesg | 无 CRC/ECC/unicam 报错 | ❌ 连错误都没有 → 数据线上一帧都没到 |
| 切另一 CSI 口（`dtoverlay=imx219,cam0` → `csi@7e800000`） | 传感器从 I2C 完全消失、`No cameras available` | ✅ 证明排线插的就是正确口，已改回 |

**结论**：软件侧（overlay、端口、分辨率、带宽、驱动）全部正常，传感器供电与 I2C 控制通道也正常，
但 MIPI 数据/时钟差分对上完全无信号 —— **排线或模块的数据通道硬件损坏**。

**下一步（按顺序）**：
1. 换一根 **15-pin / 1.0mm 树莓派摄像头专用排线**（¥3-5，最快最便宜）
   - ⚠️ 不要按"同面 A 型"下单：同面/异面只取决于两端 FPC 座触点的朝向
   - 本机实测：用户手上这根平铺时**左端触点朝下、右端朝上 = 异面 B 型**，而供电/I2C 完全正常
     → 说明 B 型（异面）才是这对座子正确的线型，按"同面"买会踩坑
   - 买的时候照着手上的线比：两端触点是否同面，须和原来一致；店家通常标 A/B 型
2. 仍不行 → 换摄像头模块（Waveshare / Arducam 正规厂货，别买无标 DC-IMX219）

> ⚠️ 注意：`pkill -f rpicam` 会连带杀掉执行该命令的 shell 自身（命令行含关键字），
> 要用 `pkill -9 -f '[r]picam-still'` 这种方括号写法。

```bash
# 执行远程命令（最后数字=超时秒数，可选，默认30）
```

## 七、视觉三件事（代码已就绪，等摄像头可用）

摄像头一旦能出帧，下面三条命令就是全部接线：

```bash
# 0. 体检：模型在不在 / 能不能出帧 / 检测器能不能跑
python3 scripts/vision_service.py check

# 1. 人脸认主人（先录入自己）
python3 scripts/face_db.py enroll --name 张三
python3 scripts/vision_service.py who

# 2. 拍照问模型（llm.json 里要有 vision 段，DeepSeek 没有视觉接口）
python3 scripts/vision_service.py snap --ask "这是什么东西"

# 3. 手势停车：手掌举到镜头前约 0.5 秒
python3 scripts/vision_service.py gesture --cmd /tmp/vision.cmd
```

| 文件 | 作用 |
|---|---|
| `scripts/vision_service.py` | 三条能力的统一入口（新增） |
| `ai助手屏幕/pi_files/vision_intent.py` | 把语音意图翻译成上表的命令（新增） |
| `scripts/face_detect.py` / `face_db.py` | 已有的检测与识别，未改动 |

**三个刻意的取舍**

1. **识别一律只输出结论，不输出控制量。** 手势只发 `[stop]`，人脸只报名字，
   和"转向闭环留在车端"是同一个原则：上位机的判断有延迟、会漏帧，不能直接进控制回路。
2. **手势进程不自己连蓝牙。** HC-04 的 SPP 同一时刻只允许一路连接，链路在
   hub 手里；手势进程只往 `/tmp/vision.cmd` 写一个 `stop`，hub 在自己的
   0.5 秒心跳里读到再发车（和风扇的 `/tmp/fan.cmd` 同一个套路）。
3. **视觉走子进程，不进主进程。** cv2 常驻几十兆内存，解码线程还会和识别、
   界面抢 GIL，一 import 语音延迟立刻变差。

**手势判定**用 YCrCb 肤色面积 + 轮廓 solidity + 连续帧数，不是"比数字"。
纯 OpenCV 做静态手势分类很不稳，而"手举到镜头前"这个动作信号量极大，
鲁棒性和演示效果反而更好。

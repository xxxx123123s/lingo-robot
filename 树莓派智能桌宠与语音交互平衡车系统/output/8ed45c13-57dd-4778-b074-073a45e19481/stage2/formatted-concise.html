树莓派智能桌宠与语音交互平衡车系统

摘要

Executive Summary

本项目以树莓派 4B 为上位机、STM32F103 平衡车为下位机，通过蓝牙串口把语音交互与触摸屏操控接入平衡车。系统实现三项能力：说出"前进""右转九十度"即可开车，并能"教一遍就自己重走"；接入大语言模型并注入实时天气，能回答"现在几度""我在做什么项目"；一块触摸屏把对话、天气、遥控、语音控车与系统监控集成在同一界面。

实测转向平均绝对误差 3.3°，90° 转向耗时 1.6 秒；带实况的问答响应 1.0 秒；风扇满占空比采样 220 次无一次欠压。硬件未做破坏性改动，车端固件改动集中于单个文件，可回退。

一、项目背景与目标

平衡车是常见的嵌入式课程载体，但多数实现停留在"能站住、能用手机 APP 遥控"的层次。手机遥控要一手持机、一手扶车，双手被完全占满。

本项目把交互方式从"手指"换成"语言"，设定四个目标：语音控车、双向通信（姿态与航向回传）、示教再现、一体化交互。最后一点是与多数语音小车的区别——它们仍依赖电脑运行识别程序，本项目把识别、对话、界面渲染全部跑在树莓派上，开机即用。

二、系统设计

系统采用上下位机架构：树莓派负责"听懂"和"呈现"，平衡车负责"走准"。数据流向如下：

        ┌──────────── 树莓派 4B（上位机）────────────┐
        │  麦克风 → VAD 切句 → sherpa-onnx 识别       │
        │              ↓                              │
        │  意图解析（本地规则）  ←→  DeepSeek 大模型   │
        │              ↓                              │
        │  动作白名单 → 蓝牙 SPP 下发                 │
        │              ↑                              │
        │  触摸屏 UI（6 个功能页）   遥测回传          │
        └──────────────┼──────────────────────────────┘
                       │ 蓝牙串口 9600 8N1
        ┌──────────────┼──────────────────────────────┐
        │              ↓                              │
        │  HC-04 → USART2 → 指令解析 → 串级 PID        │
        │                     ↑                       │
        │  MPU6050 航向积分 + 转向闭环 + 跌倒锁         │
        └──────────── 平衡车（下位机）────────────────┘

最关键的设计决定是把转向闭环放在车端：树莓派只下发意图，不参与控制。因为蓝牙有 50～100 ms 延迟且会抖动，若由上位机闭环，每拍控制量都带着延迟进入系统，车会来回振荡；把闭环放到被控对象一侧，延迟就从"控制回路的一部分"退化成"命令何时开始"，不影响稳定性。

协议沿用车端原有的手机 APP 格式，车端不必为语音功能改动：

方向报文含义
上位机 → 车[go,速度,转向]例如 [go,1.40,0] 前进
上位机 → 车[turn,角度]例如 [turn,90] 右转 90°
上位机 → 车[stop]立即停车
车 → 上位机[s,俯仰×10,速度×100,航向,状态]20 Hz 遥测

状态位 = 运行中×1 + 转向中×2 + 跌倒锁定×4 + 陀螺仪异常×8。设状态位是为了远程区分故障——"车倒了被锁死"和"转向没收敛"外部现象几乎一样，没有它只能靠猜。

四、功能实现

功能分为对话与记忆、控车与示教、触屏与散热三块，下面依次说明。

4.1 语音对话与长期记忆

对话链路为：麦克风 → VAD 切句 → sherpa-onnx 离线识别 → 意图判断 → 大模型生成 → TTS 播报。识别不依赖网络；针对控车准备了 20 个热词（前进、右转、九十度、记住这条路等），提升短指令识别率。

大模型接入 DeepSeek，但接口本身并不联网，最初问"今天天气"要么答不知道、要么编一个错误答案。解决办法是提问前先把实时数据注入提示词：open-meteo 取实况与三日预报（缓存 5 分钟），ip-api 取城市定位（缓存 1 小时），并要求"不知道就直说"。修复后可答"阴天，21 度，风 6 米每秒，降雨概率一成八"。另外分快答与讲解两档：日常问答限 40 字、0.9 秒；讲解类 100～180 字并附例子、1.5 秒。

长期记忆把用户陈述存入本地 JSON，重启后仍在。两个细节：区分陈述与疑问——"我叫张三"要记，"我叫什么"绝不能把"什么"当名字；清除记忆走本地规则，不经过模型，1 毫秒完成。

4.2 语音控车与示教再现

意图解析本地规则优先：命中规则表直接执行，解析不出才转大模型兜底。

示教再现是最有特色的功能：说"记住这条路"开始记录，指挥车走一遍，说"记好了"结束，之后说"走一遍"车就自动复现整条路径。路线以动作序列存于本地，可命名、可存多条。

安全上有三道约束：动作白名单——大模型只能从 8 个动作里挑一个，不允许输出任何速度或 PWM 数值；指令自带时长——"前进"默认 2 秒，"一直走"上限 8 秒；跌倒锁——倾角超 ±50° 后锁死，语音无法拉起，必须人工按键复位。

4.3 触摸屏与温控风扇

屏幕为 240×320 SPI 触摸屏，用应用栈管理页面，主页以磁贴进入对话、天气、温湿度、遥控、语音控车、系统六页。界面层只负责"看"和"判断点到哪"，数据由逻辑层传入，因此界面代码能在电脑上直接渲染成图片，不接硬件就能调排版。

树莓派满载时温度升到 45 ℃ 以上，因此加装一路 PWM 风扇：TB6612 驱动、GPIO12 输出硬件 PWM。40 ℃ 起转、70 ℃ 到上限，线性调速并带 3 ℃ 迟滞；启动采用软启动，6 秒分 200 步爬到目标占空比，把浪涌摊平；运行中每秒读欠压标志，检测到即自动降上限。系统页第一行是风扇开关，点击在「自动 → 手动开 → 手动关」之间循环；屏幕与风扇服务分属两个用户，不能争抢 GPIO，故通过状态文件通信，切换响应 200～260 毫秒。

五、关键问题与解决

四个有代表性的问题，每个都走完"现象 → 根因 → 修复"的闭环：

问题现象根因修复
车抽搐两下就停机说"转一圈"，车抖两下停住，8 秒内航向暴涨 3410°陀螺仪零偏标定无静止检测，偏差使航向持续累加，闭环误判"已到位"标定改 6 组 × 100 次，组内极差达标才接受；超限置"陀螺仪异常"位并拒绝转向
转圈一顿一顿转向走走停停差速量被除以 2，与平衡环修正处于同一量级，每次修正把转向顶回去差速全量叠加、设最小差速、临近目标按角度减速，90° 用时 1.6 秒
掉线仍显示"已连接"车断电后屏幕仍绿色"已连接"状态只在连接成功时写一次；断开是事件，界面读的是变量改用遥测新鲜度判活，3 秒无数据判掉线，显示"掉线"并 8 秒自动重连
风扇一跑就重启启动瞬间重启三次，SD 卡写坏一个文件2 A 电源余量不足，浪涌使电压跌破 4.63 V 阈值换官方 5.1 V / 3 A 电源，70% 与 100% 各采样 220 次，欠压恒为 0

这四类分别对应标定不可信、控制量量级失配、状态显示脱离证据、供电余量不足，都是只有真实硬件才会暴露的错误。附带一个排查技巧：get_throttled 的低 4 位表示"此刻"、高 4 位表示"曾经"，后者只有完全断电才清零，故判断新电源必须先拔电再上电，看到 0x0 才算基线。

转向误差来源已定位：陀螺仪零偏约 1.2 °/s，转 2 秒累积 2.4°，故这 ±6° 中大部分不是"转不准"而是"测不准"；引入在线零偏跟踪后可压到 ±2°。

七、总结与不足

项目完成了从"能站住的平衡车"到"能听懂话的机器人"的改造，核心工作有三处：架构上把转向闭环放在车端，使蓝牙延迟不再影响稳定性；交互上把语音、触屏、对话助手整合到一台树莓派，脱离电脑依赖；工程上用状态位、遥测新鲜度、欠压标志这类"证据型"设计，让故障可观测、可定位。

仍存在四点不足：前进距离是开环的，需编码器里程做位置控制；命令词识别率与端到端延迟尚未定量测量；转向误差仍受零偏限制；视觉跟随尚未接入，是下一步投入产出比最高的方向。

# 语音交互平衡车 —— 技术报告

> 一句话概括：**用嘴开车。** 树莓派负责"听懂"，平衡车负责"走准"，两者通过蓝牙串口通信；
> 支持连续语音控车、状态问答，以及"教一遍就自己重走"的示教再现。

| 项目 | 内容 |
|---|---|
| 名称 | 语音交互平衡车（小派 + 平衡车） |
| 语音端 | 树莓派 4B + USB 麦克风 + 3.5mm 音箱，市电供电 |
| 车端 | STM32F103 + MPU6050 + 双霍尔编码器 + HC-04 蓝牙，自带电池 |
| 通信 | 蓝牙 SPP 串口透传，9600 8N1，方括号报文 |
| 语音链路 | VAD 切句 → sherpa-onnx 本地识别 → 意图表匹配 → 蓝牙下指令 |
| 核心指标 | 转向精度 ±6°，90° 转向耗时 1.4～3.4 s，全程离线可用 |

---

## 一、要解决什么问题

平衡车原本只能用手机 APP 的虚拟摇杆遥控，人必须一手拿手机、一手扶车，无法做别的事。
本项目把它改造成**语音直接指挥**：

- 说"前进三秒""右转九十度"→ 车立刻执行，不需要手机
- 说"你歪多少度""站得稳不稳"→ 车把姿态数据回传，语音念出来（**双向通信**）
- 说"记住这条路"→ 指挥它走一遍 → 说"走一遍"→ 它自己复现（**示教再现**）

## 二、系统架构

```
              ┌──────────────── 树莓派 4B（桌上，市电）────────────────┐
 你说的话 ──▶ │ USB 麦克风 → VAD 切句 → sherpa-onnx 识别 → 意图解析     │
              │                                    │                    │
              │                        ┌───────────┴───────────┐        │
              │                    命中意图表              未命中        │
              │                   （本地，不联网）      （DeepSeek 慢通道）│
              │                        └───────────┬───────────┘        │
              │                              动作白名单                  │
              │                                    │ 蓝牙 SPP           │
              └────────────────────────────────────┼────────────────────┘
                                                   ▼
              ┌──────────────── 平衡车（地面，自带电池）────────────────┐
              │ HC-04 → USART2 → 指令解析 → 串级 PID → 电机             │
              │                    ↑                                   │
              │        MPU6050 航向积分 + 转向闭环（车端自己转到位）      │
              │                    │ 5Hz 遥测                          │
              └────────────────────┼───────────────────────────────────┘
                                   ▼  返回树莓派，用于状态问答与"转完没有"
```

### 设计上最关键的一个决定：转向闭环放在车上

树莓派**只下指令，不参与控制**。它说"右转 90°"，车自己用陀螺仪积分转到 90° 才停。
理由：蓝牙有 50～100 ms 延迟且会抖动，如果让树莓派做闭环，每一拍都带着延迟和抖动，
车会来回振荡。**把闭环放在被控对象一侧，通信延迟就退化成"命令延迟"，不影响稳定性。**

这也是很多同类项目翻车的地方：把 PID 放在上位机，蓝牙一卡车就抖。

## 三、硬件与接线

| 部件 | 型号 | 接法 | 备注 |
|---|---|---|---|
| 主控 | STM32F103C8T6 | — | 江协科技标准工程结构 |
| 姿态 | MPU6050 | I2C（PB6/PB7） | 只用 Z 轴角速度做航向积分 |
| 编码器 | 双霍尔，44 线 | TIM3 / TIM4 编码器模式 | 提供速度与里程 |
| 蓝牙 | HC-04 | USART2（PA2/PA3） | 经典蓝牙 SPP，**免驱动、免改线** |
| 显示 | OLED | I2C | 现场调试用，**未接也能跑**（遥测走蓝牙） |
| 语音端 | 树莓派 4B | 网线/USB WiFi | 麦克风 `plughw:3,0`，音箱 `plughw:2,0` |

**接线一行没动。** 蓝牙模块本来就接在 USART2，树莓派连上去后，对车来说和手机 APP 完全等价。

## 四、通信协议

报文用方括号包裹、逗号分隔，兼容原手机 APP 的 `[joystick,...]` 格式。

| 方向 | 报文 | 含义 |
|---|---|---|
| Pi → 车 | `[go,速度,转向]` | `[go,1.40,0]` 前进；`[go,-1.40,0]` 后退 |
| Pi → 车 | `[turn,角度]` | `[turn,90]` 右转 90°，`[turn,-45]` 左转 45° |
| Pi → 车 | `[stop]` | 目标速度/转向清零，立即停车 |
| 车 → Pi | `[s,俯仰×10,速度×100,航向,状态]` | `[s,12,-35,90,3]` = 仰 1.2°、速度 −0.35、航向 90°、运行中+转向中 |

状态位 = 运行中×1 + 转向中×2 + 跌倒锁定×4。这 3 个比特是为了**远程区分故障**：
"车倒了被锁死"和"转向闭环没收敛"在现象上一模一样（都只动一点点），
没有状态位时只能靠猜。

## 五、关键设计与踩过的坑

这一节是项目的技术核心。每个坑都是"现象 → 根因 → 验证"的完整闭环。

### 5.1 车停着自己往前挪

**现象**：直立不动，几十秒后自己往前走，越走越快。

**根因**（三个叠加）：

1. `PID.c` 里积分限幅那两行被注释掉了：`p->ErrorInt += p->Error0;` 之后没有任何钳位，
   积分**无限累加**；
2. 两个 `ErrorInt_min` 写成了**正数**（100、500），本该是负数，即使取消注释也会把积分锁成 ≥0；
3. 编码器 50 ms 采一次，分辨率约 0.05 圈/秒 ≈ 1 cm/s，车以 3～4 cm/s 挪动时速度环读出的是 **0**。

第 3 条是结构性的：**低于传感器分辨率的信号，本就不该送进控制器**。
所以除了修积分，还加了一个**位置环**——累加编码器里程，没有行进意图时把车按在一个点上。

### 5.2 原地左右扭

**现象**：直立时车身绕竖直轴小幅来回摆。

**根因**：`TurnPID` 是 `Kp=2, Ki=3`，积分项最大 `3×20=60`，而输出上限只有 50 ——
**积分一满就顶穿输出**，车扭过去、误差反向、积分再慢慢退回、又扭回来，形成自激极限环。

这是串级 PID 的经典错误：**积分增益比比例增益还大**（Ki/Kp=1.5）。位置式 PID 的 I 项
一般应比 P 小一个数量级。改为 `Ki=0.4`、积分限幅 `±5`，并给轮速差加 0.05 的死区。

### 5.3 用陀螺仪做转向阻尼 —— 试过，失败了

想法很好：编码器 50 ms 才更新一次，车刚被碰时转向环读不到，用 MPU6050 的 Z 轴角速度
（100 Hz）做阻尼，理论上能让车"刚一转就被压住"。

**实测失败**：车开始**持续朝一个方向慢慢转**。

原因：MPU6050 的零偏会随温度漂移，上电标定的 `GZ_bias` 几分钟后偏差就变成几个 °/s；
阻尼项分不清"车在转"还是"零偏漂了"，把恒定角速度换算成一个**恒定的转向推力**。

**结论**：对长时间站立的场景，绝对角速度不能直接进反馈。该方案已关闭，代码保留并注明前提。
答辩时这条比"一次调好"更值得讲——它说明了为什么选编码器死区而不是陀螺仪阻尼。

### 5.4 转向只转十几度

**现象**：按 A/D 车只转十几度就停，左右都一样。

**根因是符号约定冲突**：

- MPU6050 的 Z 轴按右手定则，**逆时针（左转）为正**，所以右转时航向角 `Yaw` 是减小的；
- 但转向闭环写的是 `YawTarget = Yaw + d`（`d>0` 表示右转，期望 `Yaw` 增大）；
- 闭环一发现"Yaw 朝反方向走了 15°"，就判定为正反馈，**发散保护直接收手**。

两个方向都会触发同一个保护，所以左右都只转一点点。

**修法**：

1. 航向积分取负号，让"正角度 = 右转"成立；
2. 转向 P 系数 `0.10 → 0.30`（0.10 时最后 20° 只剩 2 个 PWM，推不动电机）；
3. **新增转向方向自校准**：转出 4° 后自动判断航向该往哪边长，装反了就把坐标整体翻面一次，
   之后永久记住。换车、换模块、芯片装反都不用改代码。

### 5.5 播报把语音卡死 17 秒

**现象**：说"记住这条路"后报 `[SAPI 服务不可用]` 和 `Overrun!!! (17108 ms long)`。

**根因**：TTS 默认走 PC 上的 SAPI 服务，服务没开时 `urlopen` 等 15 秒超时，再退
edge-tts 联网又失败，合计 17 秒主循环阻塞；这期间没人读麦克风，`arecord` 缓冲区溢出。

**修法**：开机 2 秒超时探测 SAPI，不通直接用本机 `espeak`；播报放后台线程；
播报期间的识别结果直接丢弃（防止把自己的声音当成指令）。

### 5.6 安全设计

| 措施 | 作用 |
|---|---|
| 动作白名单 | 大模型只能从 8 个动作里选一个，**不允许输出任何速度/PWM 数值**（防幻觉把车甩出去） |
| 指令自带时长 | 说"前进"默认只走 2 秒；"一直走"有 8 秒硬上限 |
| 看门狗式重连 | 遥测断流 4 秒判定链路已断，自动重连，直到连回来 |
| 跌倒锁 `Fallen` | 角度超 ±50° 后锁死，语音指令**不能**把它重新拉起来，必须人工按 Key1 |
| 发散保护 | 转向时航向朝反方向跑超 15° 立刻停车 |
| 蓝牙独占 | SPP 只允许一个连接，手机 APP 与树莓派不能同时连 |

## 六、实测数据

测试条件：室内瓷砖地面，车自带电池满电，每次转向后静止 1 s 再测下一个。

### 6.1 转向精度

| 指令 | 实际转过 | 误差 | 用时 |
|---|---|---|---|
| 右转 90° | +91.0° | +1.0° | 1.6 s |
| 左转 90° | −84.0° | −6.0° | 3.4 s |
| 右转 45° | +42.0° | −3.0° | 1.4 s |
| **平均绝对误差** | — | **3.3°** | 平均 2.1 s |

**误差来源已定位**：陀螺仪零偏约 1.2 °/s，转向 2 秒就累积 2.4°。所以这 ±6° 里
**大半不是"转不准"，而是"测不准"**。改进方向是加在线零偏跟踪（静止时把残余角速度
慢慢学成零偏），预计可压到 ±2°。

### 6.2 需要现场补测的两项

| 指标 | 测法 | 记录 |
|---|---|---|
| 命令词识别率 | 每个词说 10 次，记成功次数 | 前进 __/10，右转 __/10，停 __/10 |
| 说完到车动延迟 | 录视频逐帧数，或看日志时间戳 | ____ ms |

> 答辩时"识别率 9/10"这类数字，比"识别很准"有说服力得多。建议花 5 分钟测一轮。

## 七、三分钟演示脚本

顺序刻意设计成"越演越神"，不要一上来就放大招。

| 时间 | 你说 / 你做 | 说明什么 |
|---|---|---|
| 0:00 | "你好，今天几号" | 普通语音对话链路是通的（已有成果） |
| 0:20 | "前进" | 车立刻动。补一句：**本地命令词，不联网** |
| 0:40 | **拔掉网线**，说"停" | 车照样停。证明快通道真的离线可跑 |
| 1:00 | "你歪多少度" | 车把姿态回传，语音念出来。证明双向通信 |
| 1:20 | 故意把车推倒 | 它自己停、被锁死，语音喊"前进"也不会复活 |
| 1:40 | 按 Key1 复位，说"右转九十度" | 转向是车端闭环，转到位自己停 |
| 2:00 | "记住这条路" → "前进两秒" → "右转九十度" → "记好了" → "走一遍" | 示教再现：**教一遍就自己重走** |
| 2:40 | 收尾：亮出 6.1 的精度表和 5.x 的坑 | 从"能跑"上升到"有数据、有分析" |

**第 2 步和第 4 步是别人做不出来的部分，一定留足时间。**
拔网线那一下最直观，但要注意：树莓派是通过网线 SSH 的，拔了你自己也连不上——
演示时用"关掉 PC 上的语音服务"代替更安全。

## 八、答辩预判问答

**Q：蓝牙延迟会不会让车抖？**
不会，因为闭环在车端。树莓派只发"转 90°"这个意图，转的过程由车上 20 Hz 闭环负责，
蓝牙那几十毫秒只影响"命令什么时候开始"，不影响"转得稳不稳"。

**Q：大模型会不会乱输出速度让车飞出去？**
不会。大模型只能从 8 个动作名里选一个，返回的是 JSON 白名单动作，**没有任何数值通道**。
即使它胡言乱语，最坏结果是"没听懂，不动"。另外快通道完全本地，不依赖网络。

**Q：转向精度多少？有数据吗？**
有。90° 实测 91.0°，45° 实测 42.0°，平均绝对误差 3.3°。误差主要来自陀螺仪零偏
（1.2 °/s），不是控制算法，下一步用在零偏跟踪可以压到 ±2°。

**Q：前进的距离准吗？**
不准，这是**开环**的（按时间算），地面打滑、电量变化都会影响。转向是闭环，前进不是。
要做到也要闭环，得用编码器里程做位置控制——这是已知的下一步。

**Q：和市面上的语音小车有什么不同？**
三点：① 离线命令词，不联网也能控；② 双向通信，能回答自己的状态；③ 示教再现，
语音从"遥控器"变成了"编程接口"——你是在用嘴写程序。

**Q：自己做的部分有哪些？**
车端固件改造（航向积分、转向闭环、遥测、位置环、跌倒锁、方向自校准）、
树莓派端整套控制脚本（蓝牙直连、意图解析、示教、重连）、以及 5.1～5.5 全部的
问题定位。语音识别用的是开源模型 sherpa-onnx。

**Q：遇到过最难的问题？**
5.1 和 5.2 都算。5.1 里三个原因叠加，其中"编码器分辨率不够导致速度环看不见慢速漂移"
是最难想到的——修了积分之后车还是慢慢挪，最后才想明白是**测不到**而不是**控不住**。

## 十、文件与运行

| 文件 | 作用 |
|---|---|
| `pi_files/car.py` | 主程序：语音识别、意图解析、蓝牙链路、示教 |
| `pi_files/car.json` | 配置：蓝牙 MAC、速度、超时 |

```bash
# 树莓派上
cd ~ && python3 car.py --monitor   # 只看遥测，确认链路通（第一步永远是这个）
python3 car.py --keys              # 键盘遥控，排除语音问题
python3 car.py --text "右转九十度"  # 只验证一句话的解析结果
python3 car.py                     # 正式语音控车
```

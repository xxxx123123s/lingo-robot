# 小派 · 触屏对话（ST7789 240×320 + XPT2046）

在原来的语音闭环（`talk.py` / `chat.py` / `tts.py`）外面加了一块触摸屏：
**按住屏幕说话 → 识别 → DeepSeek → 朗读**，并且把"你说了什么、它答了什么"直接写在屏上。

原三个语音脚本**一行没改**，`pet.py` 只是 import 它们的函数。

```

        │ ● 小派 待机        免提 关   │  状态条
        │                             │
        │          ( ˘ω˘ )            │  宠物脸：眨眼 / 看手指 / 竖耳朵
        │                             │
        │      ▁▂▅▇▅▂▁                │  音量条（听/说时才有）
        │ ┌─────────────────────────┐ │
        │ │ 你：今天天气怎么样       │ │  对话气泡
        │ │ 外面阴沉沉的，可能下午会 │ │
        │ │ 下雨，出门带把伞吧。     │ │
        │ └─────────────────────────┘ │
        │  ┌───┐ ┌──────────┐ ┌───┐  │  静音 / 按住说话 / 重说
        │  │ 🔊│ │ 按住说话 │ │ ↻ │  │
```

## 硬件与接线

2.4 寸 ST7789 + XPT2046 电阻触摸，SPI0 直驱（**没有**用 fbtft/fbcp，也不需要改 `config.txt`）：

| 用途 | 模块引脚 | 树莓派 BCM | 物理引脚 |
|---|---|---|---|
| 电源 | VCC | 3.3V | 1 / 17 |
| 地 | GND | GND | 6 |
| 显示时钟 | SCL/CLK | GPIO11 (SCLK) | 23 |
| 显示数据 | SDA/MOSI | GPIO10 (MOSI) | 19 |
| 显示片选 | CS | GPIO8 (CE0) | 24 |
| 命令/数据 | DC | GPIO25 | 22 |
| 复位 | RES/RST | GPIO24 | 18 |
| 背光 | BLK | GPIO18 | 12 |
| 触摸时钟 | T_CLK | 与 SCL 并联 | 23 |
| 触摸数据入 | T_DIN | 与 MOSI 并联 | 19 |
| 触摸数据出 | T_DO | GPIO9 (MISO) | 21 |
| 触摸片选 | T_CS | GPIO6 | 31 |
| 触摸中断 | T_IRQ | GPIO22 | 15 |

走线和上面不一样时，不用改代码：

```bash
LCD_TOUCH_IRQ=17 LCD_TOUCH_CS=7 python3 pet.py --check   # 临时试别的引脚
```

## 开机自启（可选）

现在 `python3 pet.py` 是前台跑在 SSH 里的，**一断连就没了**。想让它开机自动起来：

```bash
sudo cp /home/pi/pet.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now pet
```

日常操作：

```bash
systemctl status pet          # 看状态
journalctl -u pet -f          # 实时看日志（相当于前台跑）
sudo systemctl restart pet    # 改完代码重启
sudo systemctl stop pet       # 想手动跑之前先停掉它，否则会抢 GPIO 和麦克风
```

服务文件内容（`/home/pi/pet.service`）：

```ini
[Unit]
Description=Xiaopai touch pet
After=network-online.target sound.target
Wants=network-online.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi
ExecStart=/usr/bin/python3 -u /home/pi/pet.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

## 性能

| 项目 | 实测 |
|---|---|
| 整帧 240×320（153,600 字节）@40MHz | 约 36 ms |
| 上半屏局部刷新（脸 + 声波） | 约 20 ms |
| 界面帧率 | **14～16 fps**（`--spi-hz 62500000` 可到 20 fps 左右） |
| 按住说话 → 出答案 | 识别 0.6s + 大模型 0.7～1.4s + 合成 0.2s |

界面只重绘变化的部分：脸每帧都推，气泡和按钮只在内容变了才推，所以 SPI 不会占满总线。

## 排障

### 触摸没反应：先跑 `touch_check.py`

```bash
cd /home/pi && python3 touch_check.py
```

它会自己分步判断，屏幕上直接给结论：

| 屏幕上的结论 | 含义 | 该查什么 |
|---|---|---|
| `SPI DEAD` | 六个通道读回**完全一样**的值 | `T_DO` / `T_CLK` / `T_DIN` / `T_CS` 有一根没通 |
| `PANEL OPEN` | 通道值各不同，但**按压时全部不变** | 触摸面板到芯片的那条 **FPC 排线**（模块背面） |
| `ALL GOOD` | 坐标随手指变化 | 直接 `python3 pet.py` |

判断依据只有一条，但很关键：**不同命令读回不同值，就说明 SPI 是通的**。

```
TEMP 4095 | Y 4095 | Z1 0 | Z2 4089 | X 0      <- 6 个通道至少 2 种值 = SPI 通
```

如果 SPI 完全不通，这六个通道会返回同一个数字（通常都是 0 或都是 4095），
因为 MISO 上根本没有数据。而当所有值都卡在 **0 或 4095 两个极端**时，
说明 ADC 输入是**开路**的（有信号时应该是几百到三千多的中间值）——那是面板没连上，不是线接错。

### 屏幕全黑

先跑 `python3 pet.py --demo`。还黑的话确认 VCC(3.3V)、GND、BLK(GPIO18)。背光能亮、能刷色，
说明显示这一路是通的。

### 踩过的坑：gpiozero 的 `value` 不是引脚电平

`DigitalInputDevice(pin, pull_up=True)` 的 `.value` 返回的是**激活状态**，不是电平：
引脚为高（未触摸）时 `.value == 0`，被拉低（按下）时才是 `1`。
判断按下要用 `.is_active`，用 `.value == 0` 会把"空闲"当成"按下"，于是一直读空闲垃圾值。
系统层验证电平用 `pinctrl get 22` 最可靠（`hi` / `lo` 是真实电平）。

### 其他

- **`Device or resource busy`**：USB 麦是独占的，先 `pkill -f '[p]et\.py'`，
  或确认没有别的 `chat.py` / `talk.py` 在跑。
  同理，跑 `touch_check.py` 之前要先停掉 `pet.py`，否则 GPIO 被占着会报 `GPIO busy`。
- **按了按钮没声音**：看终端有没有 `[SAPI 不可用]`，即 PC 端语音服务没开。

## 和语音三件套的关系

```
pet.py
 ├── screen.py / petui.py         ← 新加的触屏
 ├── talk.py   make_rec / make_vad / speech_seconds   （识别 + VAD）
 ├── chat.py   ask_llm / load_cfg                     （大模型 + 人设）
 └── tts.py    _sapi_wav / _espeak / clean            （朗读，可被打断）
```

三个语音线程各管一件事：

| 线程 | 干什么 |
|---|---|
| 采集线程 | 一直从 `arecord` 读 0.1 秒一块的音频，算音量，丢进队列 |
| 大脑线程 | 处理命令（按下/松手/静音…），攒音频、喂 VAD、识别、问大模型、朗读 |
| 界面线程（主线程） | 收触摸事件、跑动画、按 15fps 刷屏 |

朗读用的是 `subprocess.Popen(aplay)` 而不是阻塞的 `subprocess.run`，
所以按大按钮时能立刻 `terminate()` 掉当前这句——这是"点一下就能打断"的实现方式。

# 二、触屏控制中心 `hub.py`

`pet.py` 只有一页对话。`hub.py` 把同一块屏幕变成一个**可以点来点去的控制中心**：
主页六个磁贴，点进去是独立应用，左上角 `‹` 返回。

| 磁贴 | 应用 | 内容 |
|---|---|---|
| 对话 | 原 `pet.py` 那套 | 按住说话 → DeepSeek → 朗读，脸会动 |
| 天气 | open-meteo（免密钥） | 实况温度/描述/体感、今日最高最低、降水概率、湿度、风速 |
| 温湿度 | DHT22 | 实时温湿 + 2 分钟趋势曲线；没接传感器时显示室外值并提示接线 |
| 遥控 | 蓝牙方向盘 | 按住走、松手停，转向 90° 一键，实时遥测（俯仰/速度/航向/状态） |
| 语音控车 | 本地意图表 | 说「右转九十度」直接发车，**不走大模型**，响应快 |
| 系统 | psutil | CPU 温度/负载/内存/磁盘/地址/运行时长/蓝牙/识别模型 |

## 一条总线，六个应用共用

麦克风只有一个、识别模型只加载一次（3 秒）、TTS 只有一套。所以不是"六个独立程序"，
而是**一个进程内的应用栈**：`open(key)` 切页，`leave()` 负责收尾（遥控页离开时会自动发停车）。

这样的好处很实际：

- 不会出现"两个应用抢麦克风"导致 `arecord: Device or resource busy`
- 识别模型只占一份内存（zipformer 14M + VAD 约 200MB），Pi 4B 完全够
- 切页是瞬时的，没有进程启动开销

## 启动

```bash
cd ~
python3 hub.py              # 正常
python3 hub.py --demo       # 不接麦克风，只跑界面（改 UI 时用）
python3 hub.py --mute       # 静音启动
```

调界面时不用反复对着屏幕说话。

## 遥控页怎么用

遥控页是一个**虚拟摇杆**，发的指令和手机 APP 完全一样
（`[joystick,0,LV,0,RH]`，10Hz 连续发），所以两边手感一致。

| 操作 | 效果 |
|---|---|
| 推住摇杆 | 往哪推就往哪走，**推多远离中心多快**（满推 = 速度档的值） |
| 一边推一边偏 | 可以**边走边转**，和手机摇杆一样 |
| 松手 | 摇杆回中，立刻停车（先发一包回中触发车端「松杆」，再发 `[stop]`） |
| 点 停 | 立即停车 |
| 点 − / + | 调满推速度（0.5～3.2，存在 `car.json` 的 `speed`） |

**为什么不是十字键**：这块屏是单点触摸，一次只能按一个地方，
「上 + 左」两个键同时按是不可能事件 —— 十字键做不出「边走边转」。
摇杆一个拇指就能同时给速度和转向。

**转向反了怎么办**：第一次推右，如果车往左转，把 `car.json` 里的
`"joy_turn_sign"` 改成 `-1`，离开遥控页再点回来就生效（不用重启、不用重烧固件）。

**安全兜底**：连续推超过 12 秒会自动停车。触摸屏偶尔会丢"抬起"事件，
没有这条兜底，车会一直往前跑。另外车端摇杆模式自带 500ms 看门狗：
上位机不发包，车半秒内自己停。

## 语音控车页

和 `car.py` 完全一样的一套本地意图表，只是搬到了触屏上：按住说话 → 识别 →
`parse_intent()` 匹配 → 直接发 `[go]/[turn]/[stop]`。**不经过大模型**，所以说完就动。

说不动、或者想加词，改 `hotwords.txt`（每汉字空格隔开），重启生效。

### 示教再现（在这一页也能用）

| 你说 | 它做什么 | 屏幕上 |
|---|---|---|
| 记住这条路 | 开始录，之后每条指令都记下来 | 右上角红色「● 录制中 N 步」 |
| 前进 / 右转九十度 / 停 | 照常执行，同时记一步 | 步数往上跳 |
| 记好了 | 停录、存盘到 `routes.json` | 「已存『路线N』X 步」 |
| 走一遍 / 原路返回 | 把刚记的那条重走一遍 | 「重走 N/M」→「重走完了」 |
| 有哪些路 | 念一遍存过的路线名 | 显示「共 N 条」 |

走的过程中点左上角返回，回放会立刻中止（每一步都检查当前页面还在不在）。
路线名可以改：「叫它 去实验室」，之后说「去实验室那条路」直接点名回放。

### 原地转圈

说「原地转圈 / 转一圈 / 转整圈」→ 原地右转 360°，屏幕显示「原地转一圈 · 完成」。

**一段发完，不再拆两段。** 早期版本车端有 10 秒硬超时（`YawTicks > 200`，20Hz），
而实测转速约 56°/s，360° 要 6~7 秒，余量太薄，所以 Pi 端把超过 200° 的拆成 180°+180°。
两段之间要停一次重新闭环，转起来能看出一顿。

现在固件把超时改成按角度算（`TURN_TIMEOUT_TICKS(d)`，360° 约 42 秒兜底），
`car.turn_plan()` 原样返回一段，360° 一口气转完。转向差速也从 `±difPWM/2` 改成
`±difPWM` 并加了最小差速 —— 这两件事都在 `麦克佛加喇叭/README.md` 里写了原因。

**转圈途中点「停车」会立刻停**：`VoiceCarApp.epoch` 每按一次停车 +1，后台线程每 0.1 秒
瞟一眼，变了就收手并补发 `[stop]`（车端收到 `[stop]` 会把 `YawMode` 清零，闭环当场停）。
屏幕立刻从「转向中」变成「已叫停」，实测 2.5 秒时叫停，当拍就停。

**注意这是"按住说话"的**：按住屏幕底下那个大按钮说，松手才识别。
直接对着树莓派说话不会有任何反应 —— 这是 `car.py`（免按键常驻听）和触屏页最大的区别。

## 聊天页为什么能答"今天天气"

一开始问它天气，它回"我窝在树莓派里看不到窗外呀"；问几点，它说"大概六点多"（实际下午四点）。
不是它装傻，是**它真的不知道**：`api.deepseek.com` 的接口不带联网，只有 `system` + 对话历史，
模型只能用训练时的参数去猜。网页版那个「联网搜索」是产品外面套的插件，API 没有。

现在每次提问前先自己查一遍，拼进 system：

```
【现场实况，回答时间日期天气只能用这里的数字】
现在是 2026年10月30日 周五 16:07；外面阴，21度，湿度61%，风6米每秒，
今天12到21度，降雨概率18%。这里没有的信息就直说不知道，不要编。
```

**天气直接用天气页的缓存**（`WeatherSvc.data`），不重复请求；时间取本机 `datetime`。
所以屏上显示 21 度，嘴上就是 21 度，不会打架。

实测三问：

| 问 | 不注入 | 注入后 |
|---|---|---|
| 今天天气怎么样 | 我窝在树莓派里看不到窗外呀 | 阴天，21度，风有点大，六米每秒，下雨概率一成八，出门带件外套呗。 |
| 现在几点了 | 我看看啊，现在大概六点多 | 现在下午四点零七分啦，该歇歇眼睛咯。 |
| 明天会下雨吗 | 我查不到天气呀，没联网呢 | 不知道呀，我只能看到今天的天气，明天的事可不敢乱猜。 |

注意第二行：**它原来不承认不知道，直接给了一个错的**。这才是最危险的地方。
所以 `build_system()` 里除了喂数据，还写死了一条"不知道就直说"。

### 回答长短会自动切换

人设里写着"不超过 40 个字"、`max_tokens` 只有 150 —— 这是为了 TTS 优化，喊"往前走"不能被回一段演讲。
但问"平衡车为什么能站住"就不该只给一句话。

`chat.is_deep()` 按问法判断，两档：

| | 快答 | 讲解 |
|---|---|---|
| 例子 | 前进 / 几点 / 明天会下雨吗 | 为什么天是蓝的 / 讲讲 PID |
| 长度 | ≤40 字 | 100~180 字，带一个例子 |
| 实测耗时 | 0.86s | 1.50s |

讲解模式仍然不允许列表和 Markdown，因为整段会被念出来。屏幕气泡只放得下 3 行，
所以长的回答主要靠听，戳气泡可以重念一遍。

### 它会记住你是谁

对话历史只有 6 轮、重启就清，但名字和项目不该每次重问。所以单独存一份 `/home/pi/memo.json`：

```json
{"name": "许鑫", "project": "智能桌宠"}
```

每次对话拼进 system：

```
【你记得关于主人的事】名字：许鑫；正在做的事：智能桌宠。
自然地用，不需要每条都复述，也别再问已经知道的事。
```

说「我叫许鑫」「我在做一个语音控车的项目」→ 正则抽出来立刻落盘，**这一句的回答就用上了**。
说「忘掉我的名字」「清空记忆」→ 拦在模型前面处理，不发请求。
命令行：`python3 chat.py --memo` 查看、`--forget` 清空。

踩过的坑：第一版问「我叫什么」，名字被存成了「什么」——
正则 `我叫(.{2,4})` 跟自我介绍长得一样，只能靠宾语是不是疑问词来分辨。

## 埋的几个坑（都已修）

| 现象 | 根因 | 修法 |
|---|---|---|
| 触屏里说「记住这条路」毫无反应 | 示教逻辑写在 `car.py` 的 `handle()` 里，`parse_intent()` 里根本没有；触屏页只调 `parse_intent()`，于是走到"没听懂这句" | 把判断抽成 `car.teach_intent()`，两边共用；`VoiceCarApp._finish()` 里先判示教再判车指令 |
| 重启后说「走一遍」走错路线 | `Routes.__init__` 不设 `last`，空名字查表时 `"" in k` 恒真，命中字典第一个 | 开局把 `last` 指到最后一条，`find("")` 直接返回空 |
| 遥控页一直"未连接" | `car.Link(None, port=...)` 把 `port` 传了两次，`TypeError` 被后台线程吞掉 | 改成位置参数传 `port` —— 这类错误不打印就完全看不出 |
| 底部提示文字被切掉一截 | `center_text()` 是**垂直居中**绘制，我按顶部对齐算坐标，结果压到卡片边框上 | 重新按"中心 ±5px"算安全区，全部留到 310 行以内 |
| 温湿度页温度 `--`、湿度却有值 | 天气接口返回的 `temp` 是 `int`，代码判的是 `isinstance(temp, float)` | 改成 `(int, float)` |
| 温湿度页标"室内"但数值是室外 | 没有传感器时回退到天气数据，标签却写死"室内" | 标签跟着数据来源走：`室内温度` / `室外温度` |
| 天气页城市显示英文 `Ziyang` | ip-api 返回英文地名 | 非中文地名统一显示「本地」 |
| 蓝牙断了，遥控页和语音页还挂着绿色的"已连接" | `CarCtl.status` 只在 `_connect()` 成功那一刻写一次 `"ok"`，之后再没人动它。RFCOMM 的 socket 断线时经常"假活着"，`recv` 既不报错也不来数据，所以连异常都等不到 | 新增 `CarCtl.tick()`，每帧查**遥测新鲜度**（车端 5Hz，3 秒没数据判掉线）。多一个 `lost` 状态，页面显示暖色的「掉线」而不是绿的；语音页动手前先过 `_guard()`，掉线直接提示「车掉线了，正在自动重连」，不再对空发指令 |
| 车没上电时界面一直卡在"连接中" | `Link._open_bt()` 硬编码重试 20 次 × (6s 超时 + 1.5s 间隔) ≈ 30 秒 | `Link` 新增 `tries` / `timeout` 参数，触屏端用 2 × 3 秒；失败后每 8 秒自动重试，车一上电自己连上，不用退出页面再进来 |

## 开机自启（现在就是这套在跑）

```bash
sudo cp hub.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hub
```

装好之后**不要再用 `python3 hub.py` 手动启动**，否则两个进程抢同一块屏幕和麦克风。
日常就用这三条：

```bash
sudo systemctl restart hub      # 改了代码要重启
sudo systemctl stop hub         # 临时停掉，回到命令行调试
journalctl -u hub -f            # 看实时日志（识别到了什么、发车发了什么）
```

`hub.log` 那个旧办法不用了，日志统一进 journal。

**注意**：`pet.service` 和 `hub.service` 都会独占屏幕和触摸，只能启用一个。

```bash
sudo systemctl disable --now pet     # 用 hub 就把 pet 关掉
```

## 和 `car.py` 不能同时跑

两者都要连车上那块蓝牙（SPP 只允许一个连接）。要么在电脑上跑 `car.py`，
要么在屏幕上点「遥控／语音控车」，**不要两个一起**。

同理，手机 APP 和它们也不能同时连。
